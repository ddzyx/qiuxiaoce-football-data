# 历史样本评估（backtest）

## 1. 适用意图与反例

适用：了解官网已发布研报的历史样本表现，或复盘用户自己查过/买过的数据。"最近准不准"、"历史命中率"、"我之前查的那些比赛结果怎么样"。

不适用：未来比赛的预测（走 match_query）；用户自己数据的纯统计（直接查本地库，不调接口）。

## 2. 参数识别

- "最近"默认近 30 天；"上个月/上周"换算成日期区间；
- 球队/联赛关键词归一化后用于 `--search`；
- 未给条件先用默认（近 30 天、每页 10 条）跑概览，再按反馈收窄。

## 3. 取数步骤（本地优先）

1. **先查本地库**（0 点）：用户问「我之前查过/买过的」一律先：
   ```bash
   python scripts/local_store.py query --sql "SELECT date, home_team, away_team, actual_score, is_correct FROM reports ORDER BY date DESC LIMIT 50"
   ```
   本地数据够回答就不再调接口。
2. 官网历史样本（**高成本，必须用户确认**）：`query_backtest.py` 底层是 `/posts` 按天批发，**1000 点/次**。调用前必须先向用户说明：「检索球小策历史研报每次 1000 点（约 10 元），确认后执行？」，得到确认才运行；翻页同样按次计费，逐页追加前一并确认预计页数。
   ```bash
   python scripts/query_backtest.py --search <关键词> --date <YYYY-MM-DD>
   ```
   （自动落 `reports` 事实表。）
3. 聚合口径：`GET /review?days=N`（10 点）或 `GET /stats/overall`（5 点）——一次返回，不要逐日拉 `/posts`。
4. 落库清单：研报摘要/全文 → `reports`；赛果 → `fixtures`。

## 4. 输出规则

- 交代样本边界：筛选条件、时间范围、样本量、缺失（多少场无赛后结果）；
- 统计只能称「历史样本表现」「一致率」，禁止外推为未来概率；
- 用户要完整复盘报告 → 加载 `templates/template_backtest.md`。

## 5. 合规红线

见 SKILL.md 第 6 节。历史样本仅用于复盘与方法评估，不提供投注建议。
